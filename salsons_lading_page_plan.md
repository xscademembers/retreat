1. Executive Summary
Salsons Retreat has spent ₹2,504 across 186 clicks and 5,641 impressions on Google Search and produced zero conversions. The campaign isn’t failing because nobody is searching — it’s failing because the landing page experience is sending the wrong signal to both Google’s Quality Score system and to potential guests.
This document is a complete, build-ready plan for a new landing page that addresses the three pillars of Quality Score:
•	Expected click-through rate — addressed via tighter ad-to-page message match and keyword-aligned headlines.
•	Ad relevance — addressed via segmented sections that mirror the searcher’s intent (day outing vs stay vs family vs couples).
•	Landing page experience — the biggest lever. Addressed via fast load times, mobile-first design, location transparency, trust signals, and a single, dominant call-to-action.

The single biggest fix
Searchers who type “resorts in vizag” expect a resort in or right next to Vizag city. Salsons Retreat is in Thatipudi, ~70 km away. The current page does not address this expectation gap honestly. Every section of the new page must reinforce a clear, repeated frame: a 90-minute lakeside escape from Vizag — worth the drive.
Targets after launch:
•	Quality Score: 7–10 across head terms within 30–45 days of launch.
•	CTR: 5–8% on top keywords (currently 3.3% blended, 0% on many).
•	Conversion rate (calls): 4–8% of clicks (currently 0%).
•	Cost per call: under ₹400 (currently ∞).
 
2. Diagnosis — Why the Current Page Scores 3/10
Quality Score is determined by Google for every keyword based on three factors. Here is where the current Salsons Retreat page is failing on each:
Quality Score Factor	Current Status	Likely Cause
Expected CTR	Below average	Generic ad copy that doesn’t reflect the searcher’s specific intent (day outing vs stay vs family).
Ad Relevance	Below average	Ads target “resorts in vizag” but landing page leads with “farmstay in Thatipudi” — message mismatch.
Landing Page Experience	Below average	Location/expectation gap, slow mobile load, no immediate trust signals, weak CTA hierarchy, missing distance/directions content, no FAQ addressing common objections.

2.1 Evidence from the search terms data
Across all 186 clicks, conversions = 0. The data tells a clear story:
•	High-intent keywords like “resorts in vizag with private pool for family” (5 clicks, 14.71% CTR) and “pet friendly resorts in vizag” (2 clicks, 66.67% CTR) drove people to the page — and none converted. These aren’t weak keywords; the page isn’t catching them.
•	The single most expensive term, “resorts in vizag” (₹243 spent, 18 clicks), produced zero calls — strong evidence the page doesn’t answer “is this what I was looking for?” fast enough.
•	Mobile-first matters: ~85% of these searches in tier-2 cities are on phones. Any LCP > 2.5s or layout shift kills mid-funnel intent.
•	Branded competitor terms (novotel, radisson, haritha, sai priya, sunray, mayfair) are bleeding budget unless excluded — these searchers want a specific brand, not Salsons.

Always-on	Sticky “Call Now” bar pinned to bottom of viewport
6.2 Visual style
•	Colour palette: keep it natural — deep green (foliage/lake), warm gold or terracotta accent (sunset/Andhra warmth), off-white background. Avoid pure black; readers in bright sunlight on mobile struggle with contrast extremes.
•	Typography: a single sans-serif throughout (Plus Jakarta Sans, Inter, or Manrope). H1 = 32–40px on mobile. Body = 16–17px. Line-height 1.5+.
•	Imagery: real photos only — no stock. Drone shot of the lake in the hero. Photos of food, pool, families at the property. Compress to <150KB each, serve as AVIF/WebP with JPG fallback.
•	Iconography: thin-line icons (Material Symbols Outlined, already loaded on the current site, or Lucide). Consistent stroke width.
•	White space: generous. The current page feels cramped because every section lacks breathing room. Use 40–80px vertical padding between sections on mobile, 80–120px on desktop.
6.3 CTA design
•	Primary CTA: gold/accent fill, white text, full-width on mobile, min 48×48 tap target.
•	Secondary CTA: outline-style, same height as primary.
•	Use a phone icon (☎) inside the button — Indian users recognise this pattern from booking sites.
•	Sticky bottom bar on mobile: 64px tall, gold/accent fill, “Call ☎ +91-XXXXX” label. Only hide it during the hero section.
 
7. Technical & SEO Specs (Developer Handoff)
7.1 Performance — Core Web Vitals targets
Quality Score weights landing page experience heavily, and Google measures this through Core Web Vitals. The current site loads from external Wix CDN and uses CDN-loaded Tailwind, both of which add render-blocking time. Targets:
Metric	Target	Current likely status	How to fix
LCP (Largest Contentful Paint)	< 2.0s	> 3s on 4G	Self-host hero image as AVIF, preload it, set explicit width/height
INP (Interaction to Next Paint)	< 200ms	Unknown	Defer non-critical JS, avoid heavy carousels
CLS (Cumulative Layout Shift)	< 0.05	Likely > 0.1	Reserve space for images and embeds (width/height attrs)
TTFB	< 800ms	Wix-served	Move to a faster host or Cloudflare CDN if staying on Wix
Total page weight	< 1.5 MB	Likely > 3 MB	Compress images, drop unused JS (Tailwind CDN), audit fonts
7.2 Mobile-first build rules
•	Build the page as static HTML where possible. The current site is a React SPA which delays first paint.
•	All images: srcset + sizes attributes; AVIF first, WebP second, JPG fallback.
•	Hero image: preload (<link rel="preload" as="image">) and serve at exact rendered dimensions per breakpoint.
•	Lazy-load everything below the fold using loading="lazy" on <img> and content-visibility: auto on heavy sections.
•	Self-host fonts (woff2). Subset to Latin only. Use font-display: swap.
•	Minimum tap target: 48×48 px.
•	All forms (if any): use input modes (inputmode="tel") for mobile keyboards.
7.3 Schema.org structured data (required)
Add the following JSON-LD blocks in the <head>:
•	LodgingBusiness — name, address, geo, telephone, priceRange, image, starRating, amenityFeature.
•	FAQPage — for the FAQ section. Each Q&A as a Question/Answer pair.
•	AggregateRating — pulled from Google reviews.
•	BreadcrumbList — even on a single landing page, helps Google’s SERP rendering.
Sample LodgingBusiness JSON-LD (developer to populate exact values):
{ "@context": "https://schema.org", "@type": "LodgingBusiness", "name": "Salsons Retreat", "image": "...", "telephone": "+91-XXXXX", "priceRange": "₹990–₹X,XXX", "address": { "@type": "PostalAddress", ... }, "geo": { "@type": "GeoCoordinates", ... }, "amenityFeature": [...] }

8. Tracking & Conversion Setup
Zero conversions in the data is a partial setup problem too — call clicks aren’t being fired as conversions in Google Ads. Fix this on the new build so future Quality Score is fed real conversion data.
8.1 What to track
Event	When it fires	Where it goes
call_click_primary	User taps the hero phone CTA	GA4 + Google Ads (as Conversion)
call_click_sticky	User taps the sticky bottom bar	GA4 + Google Ads (as Conversion)
call_click_final	User taps the final-CTA call button	GA4 + Google Ads (as Conversion)
whatsapp_click	If WhatsApp link is added later	GA4 + Google Ads
scroll_75	User scrolls past 75% of page	GA4 (engagement signal, not conversion)
form_submit (if added)	Lead form submitted	GA4 + Google Ads (as Conversion)
8.2 Implementation notes for the developer
•	Use Google Tag Manager (GTM) — the existing site is loading gtag.js directly which makes future event additions painful.
•	Wrap each tel: link with a click handler that pushes a dataLayer event before navigation.
•	In Google Ads, mark call_click_* as the primary conversion. The current site is firing a generic ‘conversion’ tag at value 990 — replace that with phone-call-specific events.
•	Keep Microsoft Clarity (already on the current site) for heatmap data — it’s the cheapest way to see what’s working post-launch.
•	Set up Google Ads call extensions on the campaign in parallel — these often outperform on-site CTAs for this audience.
